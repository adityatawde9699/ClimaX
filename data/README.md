# ClimaX Data Architecture & Management

This directory defines the schemas, mock samples, and seed fixtures governing the ClimaX data ecosystem.

## 1. Directory Structure

```text
data/
├── schemas/    # Declarative JSON Schemas for domain validation
├── samples/    # Concrete representative JSON payloads across the 4-tier taxonomy
├── fixtures/   # Seed database fixtures for local development
└── README.md   # Data lifecycle, privacy, and architectural guidelines
```

---

## 2. The 4-Tier Data Lifecycle

Every environmental datapoint in ClimaX is tagged with an immutable `tier` indicator:

1. **OBSERVED** (`data/samples/observation_sample.json`, `data/samples/citizen_report_sample.json`):
   - Physical telemetry from low-cost sensors (PMS5003), regulatory stations (BAM-1020), or raw citizen photo uploads.
   - Preserved verbatim with source attribution and timestamp.
2. **INFERRED** (`data/samples/ai_analysis_sample.json`):
   - Model-deduced hypotheses generated by Gemini 1.5 Pro / Flash.
   - Includes confidence score, confidence tier, and explicit visual/meteorological evidence.
3. **PREDICTED** (`data/samples/prediction_sample.json`):
   - 6-hour, 24-hour, and 72-hour forward-looking plume and AQI estimations from Vertex AI sequence models.
   - Bound with statistical uncertainty intervals.
4. **VERIFIED** (`data/samples/verification_sample.json`):
   - Ground truth recorded by certified municipal environmental officers following physical site inspections.

---

## 3. Privacy & Geospatial Masking

- **Citizen Location Privacy**: Exact citizen mobile coordinates are stored in secure, encrypted tables accessible only to authorized municipal field officers. Public-facing maps and citizen feeds render obfuscated coordinates with an intentional jitter/blur radius of 200m.
- **Media Redaction**: Automated pre-processing blurs human faces and vehicle license plates before storing citizen photos in Google Cloud Storage.
